# AgriSahay Usability Evaluation & Pilot Study Protocol

## 1. Research Objectives & Methodology

The AgriSahay Pilot Study framework is structured to empirically evaluate:
> *"Does an explainable, offline-first, multilingual, and climate-aware agriculture lending platform improve rural credit accessibility, officer efficiency, and borrower comprehension?"*

### Cohort Representation
Participants represent four key user segments in rural and semi-urban banking:
1. **Marginal & Small Farmers** (Cultivators holding $< 2$ hectares, varying digital literacy).
2. **Agriculture Relationship Officers (AROs)** (Field staff navigating village visits and low connectivity).
3. **Branch Credit Managers** (Underwriters handling sanction committee dockets and restructuring).
4. **Rural Banking Customers** (Farmers accessing passbooks, crop loss claims, and consent receipts).

---

## 2. Standard Evaluation Tasks (T1–T6)

Researchers conduct timed trials across 6 standard banking tasks:

| Task ID | Standard Task Description | Traditional Manual Baseline | Primary Success Metric |
| :--- | :--- | :---: | :--- |
| **T1** | Complete Farmer Onboarding & DPDP Consent | 1,800 sec (30 min) | Elapsed time & form error rate |
| **T2** | Calculate Crop Scale of Finance Loan Limit | 900 sec (15 min) | Accuracy & elimination of manual lookup errors |
| **T3** | Generate Harvest-Linked Repayment Schedule | 1,200 sec (20 min) | Matching gestation period to harvest month |
| **T4** | Log Localized PMFBY Crop Loss (72-hr Window) | 2,400 sec (40 min) | Prompt intimation before 72-hour statutory cutoff |
| **T5** | Complete Offline Village Field Visit & Sync | 1,500 sec (25 min) | Zero data loss upon online reconnection |
| **T6** | Review 7-Factor Resilience Score & Override | 1,200 sec (20 min) | Officer comprehension of explainability breakdown |

## 3. Brooke (1986) System Usability Scale (SUS)

Participant feedback is gathered using the standard 10-item System Usability Scale on a 1–5 Likert scale:

1. I think that I would like to use this system frequently.
2. I found the system unnecessarily complex.
3. I thought the system was easy to use.
4. I think that I would need the support of a technical person to be able to use this system.
5. I found the various functions in this system were well integrated.
6. I thought there was too much inconsistency in this system.
7. I would imagine that most people would learn to use this system very quickly.
8. I found the system very cumbersome to use.
9. I felt very confident using the system.
10. I needed to learn a lot of things before I could get going with this system.

### Scoring Formula:
$$\text{Score} = 2.5 \times \left[ \sum_{i \in \text{odd}} (R_i - 1) + \sum_{i \in \text{even}} (5 - R_i) \right]$$

- **Score Range**: 0 to 100.
- **Interpretation**:
  - $> 80.3$: Grade A (Excellent)
  - $68.0 - 80.2$: Grade B (Good)
  - $51.0 - 67.9$: Grade C (Fair)
  - $< 51.0$: Grade D / F (Unacceptable)

## 4. Zero-Fabrication Integrity Policy

To preserve scientific rigor:
- When first loaded, the Research Evaluation Dashboard displays **"No study data collected yet"**.
- Researchers may click **"Load Sample Study Data"** to demonstrate visualization capabilities during presentations, which immediately displays an amber warning banner:
  > *"Sample / Demo Study Data Active: Numbers displayed are illustrative sample artifacts for testing and demonstration, NOT actual academic research results."*
